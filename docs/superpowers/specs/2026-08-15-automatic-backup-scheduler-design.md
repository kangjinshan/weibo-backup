# 30 分钟自动备份设计

## 目标

监控后台启动后立即尝试启动一次微博备份，随后每 30 分钟再次尝试。定时访问可以缩短 Cookie 长时间闲置的窗口，但不能保证微博永不主动使 Cookie 失效；现有 Cookie 状态检测和人工更新入口继续保留。

## 方案选择

采用 FastAPI 进程内的异步定时任务。相比系统 cron，它不需要在每台 NAS 或容器上维护额外部署配置；相比网页定时调用，它不依赖浏览器页面持续打开。

定时器默认启用，间隔由 `WEIBO_AUTO_BACKUP_INTERVAL_SECONDS` 控制，默认值为 `1800`。将该值设为 `0` 可关闭自动备份，便于特殊部署或故障排查。

## 组件和数据流

1. FastAPI 生命周期启动时创建一个后台 asyncio 任务。
2. 任务立即调用一次内部备份启动函数，然后等待配置的间隔并重复。
3. 内部启动函数由手动 `/api/backup/start` 接口和自动定时器共同复用，负责检查已有进程、读取并验证配置、创建爬虫进程、写入 pid 文件。
4. FastAPI 生命周期结束时取消并等待定时任务退出；已经启动的独立爬虫进程不被强制停止。

## 并发和状态规则

- 已有备份处于 `running` 或 `paused` 时，本轮自动触发跳过，不创建第二个进程。
- 配置文件缺失、账号 ID 为示例值、Cookie 为示例值或启动进程失败时，本轮失败，定时器继续存活并在下个周期重试。
- 后台启动后的第一次尝试不等待 30 分钟。
- 每次尝试完成后再等待一个完整间隔；启动爬虫本身只创建子进程，不等待爬取结束。
- 当前启动脚本使用单个 Uvicorn worker。多 worker 部署不在本次范围内，README 会明确保持单 worker，以免每个 worker 各自创建定时器。

## 错误处理与安全

- 自动任务捕获单次触发中的异常，记录不包含 Cookie 明文的状态或错误消息，不能因为一轮失败而永久退出。
- 配置读取 API 仍只暴露 `cookie_configured`、`cookie_status` 和配置问题，不新增 Cookie 明文输出。
- 自动定时器不调用本机 Cookie 助手，也不扩大 loopback Cookie 接口的访问范围。
- 自动任务不绕过现有 `backup_config_issues()` 校验。

## 测试

- 单元测试验证启动后台任务后会立即触发一次。
- 单元测试验证后续触发之间等待配置间隔。
- 单元测试验证单次启动异常不会终止循环。
- 单元测试验证生命周期关闭时取消任务。
- 现有手动启动测试继续验证配置校验、重复进程保护和 JSON 错误响应。
- 运行仓库规定的 Python、Node、语法和 JSON 验证命令。
